## 🔴 CRÍTICO — Segurança (não abrir alpha neste estado)

1. **Sandbox não isola código arbitrário em produção** (`backend/app/sandbox/runner.py:286-410` + `docker-compose.yml:17`)
   - O provider `local-process` executa o código do competidor **direto no host**, herdando `os.environ` (API keys, DATABASE_URL) — exfiltração trivial.
   - O compose força `local-process` e o container não monta o socket do Docker → o Docker provider falha e cai no local de qualquer forma.
   - **Hidden tests ficam legíveis pelo código arbitrário** (`runner.py:160-164`): o competidor pode ler `/sandbox/hidden_tests/*.py` e vazar via stdout → quebra a avaliação.
2. **`GET /battles` e `/battles/{id}` são públicos e retornam `workspace_files` completos** (`backend/app/api/v1/battles.py:37/61`) → qualquer um lê a submissão do oponente (cheating) e possíveis segredos embutidos.
3. **Defaults perigosos:** `ENABLE_MOCK_GITHUB_AUTH=true` + invite `"*"` (`backend/app/core/config.py`, `backend/app/services/alpha_store.py:294-306`) → qualquer um autentica como qualquer github_login.
4. **`INSERT OR REPLACE` por id previsível** (`alpha_store.py:500-517`) → sobrescrever o profile de outro dono.
5. **Sem allowlist de executor** (`public_alpha_service.py:132-135`, `agent_profile.py:53-57`) → usuário pode acionar executors Claude/OpenAI pagos na quota do servidor.

## 🟠 MÉDIO — Bugs funcionais concretos

### Backend (FastAPI)
- `runner.py:311/318/227/231` — timeout de `subprocess.run` recebe **minutos** como segundos; quest longa roda fração do tempo.
- `public_alpha_service.py:239-252` — `start_battle` com check-then-act não atômico → battle roda 2× (custo LLM 2×).
- `join_battle`/`submit_for_battle` sem guarda de status (`:195-237`) — após battle concluída/falha, participante pode re-submeter e voltar status a "ready".
- Fallback prometido para submissão não existe (`:356-371`) — executor vazio → submissão humana descartada com score 0.
- SSE `q.get(timeout=30)` desconecta battles longas sem aviso (`battle_event_bus.py:57`).
- Falha de sandbox → HTTP 500 e run órfã "created" sem retry (`runs.py:100-110`, `execution_service.py:36`).
- Leaderboard reprocessa ELO em ordem cronológica **inversa** e refaz tudo a cada chamada (N+1) (`alpha_store.py:824-893`).
- `rate_limit.py:35-36` — limita por IP único, ignorando `X-Forwarded-For` (DoS mútuo atrás de proxy).

### Frontend (Angular)
- `pages/quest-lobby/quest-lobby.ts:59-94` — cria profile como efeito colateral de um GET; default `'buildknight'` hardcoded quebrado se POST falhar.
- `pages/battle-room/battle-room.ts:62-69` — polling infinito que nunca para em estado terminal; `catchError(()=>of(null))` engole erro e pisca "battle não encontrada".
- `pages/result/result.ts:36-45` — um artefato ausente (404) derruba o painel inteiro.
- `pages/dashboard/dashboard.html:97-108` — "Minhas battles" lista **todas** as battles do backend (GET público).
- URLs hardcoded `localhost:8000` em todos os services — quebra em qualquer outro ambiente.
